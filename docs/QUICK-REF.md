## 2. System Diagram (condensed)

*Source: [`docs/01-architecture.md`](01-architecture.md) §1.1*

```
Web Learner ──(1) Auth JWT──►  Supabase (GoTrue · Postgres 15 · RLS · Storage)
             ──(2) Data RPC──►       ▲  data flows via PostgREST / RPC
Web Admin    ──(Prisma TCP)──►       │
             ──(Storage)───►         │
                                     │ (3) verify ES256 (JWKS) / HS256 JWT
AI Server (FastAPI) ◄────────────────┘
  TARGET: POST /v1/gec/correct → T5-small corrected_text + deterministic diff
  LEGACY COMPATIBILITY: /v1/srs/schedule and /v1/chat/roleplay
  MOCK_MODE=true → deterministic response with target schema
```

**Key invariant:** Web Learner does NOT call Supabase for AI inference — only for core data.
AI Server is stateless; it never reads/writes Supabase directly. Learner AI calls go through a
Next.js Route Handler proxy in `lingora-web` that forwards the JWT and owns the 8s timeout.
If AI Server is down, deterministic SRS and the core lesson flow remain usable; scenario writing shows a recoverable GEC error.

## 5. AI API Endpoints

*Source: [`docs/03-api-contract.md`](03-api-contract.md)*

### Target: `POST /v1/gec/correct`
- **Input:** `{ text, scenario_code, lang: "en", client }`
- **Output:** `{ original_text, corrected_text, corrections?, suggested_text?, explanation?, model_version, is_mock, latency_ms }`
- T5-small owns only corrected text; diff/classification are deterministic derived modules.
- GEC output is transient in MVP. Legacy SRS/chat endpoints remain compatibility surfaces until migration.

### Other endpoints
| Method | Path | Purpose |
|---|---|---|
| `GET` | `/v1/model/info` | Model name/version/dataset/metric — for reports |
| `GET` | `/v1/chat/scenarios` | Published scenarios list |
| `GET` | `/health/live` | Liveness (no model dependency) |
| `GET` | `/health/ready` | Readiness (SRS + NLP loaded) |

**Error envelope:** `{ "error": { "code": "…", "message": "…", "detail": {…} } }`
**All fields:** `snake_case`; inference path version prefix: `/v1/`

## 6. Key Database Tables

*Source: [`docs/04-data-model.md`](04-data-model.md) — canonical Prisma schema and approved logical baseline*

| Table | Purpose |
|---|---|
| `profiles` | Extends `auth.users`; stores role (`LEARNER\|ADMIN`), `uiLocale`, `nativeLangCode`, `streakCount` |
| `courses` + `course_translations` | Language courses, i18n titles; RLS: published → read; ADMIN → write |
| `lessons` + `lesson_translations` | Ordered lessons within a course |
| `vocabularies` + `vocabulary_translations` | Vocabulary terms; optional `audioUrl`; unique by `(languageCode, normalizedTerm)` |
| `lesson_vocabularies` | Junction: lesson ↔ vocabulary with `orderIndex` |
| `exercises` | `type` ∈ `{MCQ, FILL_BLANK, REORDER}`; JSONB `payload` |
| `user_progress` | `(userId, lessonId)` unique; `status`, `score` (0–100 int), `completedAt` |
| `user_vocab_srs` | SRS card per (user, vocab); `recallProbability`, `nextReviewAt`, `easeFactor` |
| `review_logs` | Immutable vocabulary review events used by deterministic SRS and future analysis |
| `chat_scenarios` + `chat_scenario_translations` | Roleplay scenarios; `code` unique (e.g. `hotel_booking`) |
| `chat_sessions` | One session per user/scenario attempt |
| `chat_messages` | Ordered by `sequenceNumber`; `role` ∈ `{USER, AI}` |

**RLS boundary:** Learners read their own rows; Admins write content; `user_vocab_srs` / `review_logs` write only via `record_review` RPC.
**`record_review` RPC:** atomic transaction — inserts `review_logs` + updates `user_vocab_srs` in one call. Derives identity from `auth.uid()`.

## 8. Key Constraints & Principles

*Source: [`docs/00-master-plan.md`](00-master-plan.md) §0.1–0.2*

**Assumptions in effect:**
- G1: ~12 weeks total (from 2026-08-13) — M1.3 consumed weeks 1–2.
- G2: Learning language = English; UI locales = `vi`, `en` (`ja` P2).
- G3: ML/Deep Learning = T5-small for English GEC; no separate NLP chatbot track.
- G4: Solo developer, 3 roles (SE + ML + NLP).
- G5: GPU = Google Colab / Kaggle free (T4/P100).
- G6: GEC dataset/license/split must be approved before training; no fabricated metrics.

**Non-negotiable principles:**
1. Working system state every week (not necessarily a production deploy).
2. Mock first, real later — every Web screen must run on mock before real AI is connected.
3. AI is an additive feature, not a blocker — app must demo without AI.
4. Write reports in parallel, not at the end.
5. SRS and Chatbot are independent — one late does not block the other.
6. NLP cannot delay SE — always use `MOCK_MODE` if model not ready.
7. Do not upgrade libraries mid-project without approval.
