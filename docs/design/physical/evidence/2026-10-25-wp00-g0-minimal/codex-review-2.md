## Remaining MUST defects and safety impact

**B1 — caller-selected namespace (M01/M04).** `--runs-dir /other/root` is parsed by the production CLI and becomes the trusted expected root. A same-task compatible record/fixture/home from another context can be inspected, started, stopped, destroyed or queried without belonging to the pinned package namespace. Hardcoding two old forbidden run paths does not constrain arbitrary roots. The child tests introduced this flag instead of using a trusted test bootstrap. Minimum direction remains pin normal production root and keep test context separate; not a new framework/ownership design.

**B2 — initial ambiguity not counted (M03).** In the post-prepare response, filtering out wrong tuple entries before counting hides a contradictory same-ID candidate. D0 proves ID alone does not enforce project/branch. Count/reconcile relevant candidates before authorizing the initial start, using the same exact-identity rule as existing operations. This is one malformed/ambiguous binding class already in M03; no full schema cross-product.

**B3 — pending effect remains executable (M04/M06/M08).** `destroyStack` lacks the pending guard added to start/stop/public data. A previous destroy/stop/start timeout can still have an operation in flight; retry destroys after another snapshot rather than retaining the same uncertain intent. `runScaffold:99–108` calls the shared data helper directly without pending denial; that helper can connect/query/fetch while the prior effect is unknown. F3 :1900 tests **stop** on a pending-destroy record, so it cannot catch destroy retry or scaffold bypass. Conservative deny/retain is the required minimum, not successful recovery.

**B4 — claimed paused-client proof is manual lock contention (M05).** F4 :2051–2064 has no running data client or delayed end promise: it manually holds a lock exactly like L01. The gate asks for one actual data-through-close contention proof, not more concurrency combinations. Static awaited normal-close code is improved, but the required end-to-end assertion is still missing. No mutation testing is needed.

**B5 — required known-process read can become absence (M07).** Node existsSync false does not distinguish ENOENT from inability to observe. For an already known target PID, failed stat and PID-directory visibility therefore produce ABSENT→DEAD; association scans can then omit that process and return KNOWN empty. A stop/destroy postcondition may be declared and recovery credentials deleted without positive quiescence. This concerns the **required known target**, not unrelated host PIDs or exhaustive socket attribution. `checkFileAbsence` solves the analogous native-file branch, but not this process branch.

**B6 — public library error boundary / representative sinks (M09).** Lifecycle/data exports have finally-only wrappers, not a finite error boundary. For example, initial provider composition service strings become member_map keys; manager:512 interpolates a missing service into an Error when the next status disagrees. That provider-derived value escapes startStack/probeDataReadiness; Node test error output or R01's emergency `err.message` logger publishes it. A control-secret canary placed there can cross the public sink even though SQL/fetch's own mappers are static. This is a static reachable counterexample, **not an observed new secret incident**. E01/E02 PG/fetch reachability is now genuine; nevertheless checking Error.message alone does not prove stdout/stderr/child/failed-teardown sinks. One representative public-boundary test suffices; all internal variants remain SHOULD.
