Test one such escape, hostile env selection, and normal private fixture. No ancestor/UID cross-product needed.

**F2 — durable intent (M02).** Required authority persistence failures, including directory fsync, must propagate before provider mutation. At prepare adapter assert the durable record/intent exists with correct tuple. Inject one required-persistence failure through production flow and prove zero CLI/data effects and retained prior authority; do not add exhaustive FS crash testing.

**F3 — exact current ownership and pending denial (M03/M04/M06).** Missing initialized anchor on an existing BOUND operation must deny, not become first initialization. The exception is only the current unbroken fresh prepare→first start operation. Reject duplicate/foreign candidates. For uncertain pending prepare/start/stop/destroy, prefer RECOVERY_REQUIRED with same record/ID and zero further mutation/data; complete automated recovery is NOT required. One tuple alone is not prepared-state continuity, and `stacks` missing is never authoritative absence. Do not overwrite pending flags or blindly retry effects. Focused cases: same-ID replaced/missing anchor, wrong post-prepare tuple, lost response with registration and zero-match uncertain, pending destroy absent/changed/malformed inspection; counters and retained record, no broad matrix.

**F4 — one actual data authorization boundary (M05/M08).** Reuse one under-lock validator/data flow for initial/existing start, public data and scaffold; check fresh exact live identity/runtime/owner/config/continuity/endpoints using D0 shapes before any transport. No synthesized endpoint/default or stale start.env authorization. Keep typed PG/no URI/PG fallback and fixed HTTP path/origin/redirect rules. Await client lifetime; close failure must not become READY/clear authority as completed. Test missing/wrong live evidence and stale credentials with zero transports, actual typed destinations, and paused client through close blocking a destroy contender. This is the contract's one concurrency case, not exhaustive combinations.

Use available exact native metadata/known identities, not an all-host readability requirement. Distinguish native state/owner ENOENT from EACCES/other errors.
