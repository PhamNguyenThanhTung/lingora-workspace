| FTR-02 · P2 | **RESOLVED AT TECHNICAL CONTRACT LEVEL; A1 NOT EXECUTED** | Server reserves email and a UUID correlation before the provider call. `createUser` supplies that UUID and atomic private `app_metadata` marker; reconcile through `getUserById`, then bind PENDING. See spec §4. | A1 must prove actual provider UUID preservation, trigger behavior, invite/activation and recovery at every interrupted boundary. Unsupported provider behavior stops this slice; no silent fallback to email-only adoption. |
| FTR-03 · P2 | **RESOLVED AT TECHNICAL CONTRACT LEVEL; A2 NOT EXECUTED** | Lock owners get exact SELECT columns and one lock-column UPDATE grant, independently scoped SELECT USING and UPDATE USING policies. Lock-only roles have `WITH CHECK (false)` and no mutation wrapper. Runtime has no role membership/bypass. Frozen sources must be lockable in their permitted governance scope. See spec §5–6. | A2 must show legitimate locks succeed under FORCE RLS, genuine UPDATE fails for lock-only roles, foreign rows/privilege escalation fail and pooled subject does not leak. |
