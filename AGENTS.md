# Lingora — Quy tắc làm việc thực dụng

Áp dụng từ 2026-10-28 theo chỉ thị của chủ dự án. Yêu cầu mới nhất của người dùng được ưu tiên. Quy trình preapply, Stage A/Stage B và gói `WP-DB-REMAIN-01` đã bị hủy; các yêu cầu audit/hash/review trong tài liệu và kế hoạch cũ không còn là cổng chặn code tính năng.

1. **KISS — Keep It Simple:** Hiểu code và Git state trước khi sửa; chọn thay đổi nhỏ nhất phù hợp kiến trúc hiện có. Không viết thêm SQL Trigger phức tạp, SHA-256 manifest kiểm tra code hoặc script tự audit schema. Không tự mở lại các vòng kiểm duyệt cũ.
2. **Backend-First Validation:** Viết kiểm tra form, quyền Giáo viên/Admin và trạng thái bài học bằng TypeScript/JavaScript ở Backend với Zod/Prisma; không đưa nghiệp vụ mới xuống PostgreSQL Trigger. Giữ FK, UNIQUE, NOT NULL và CHECK cơ bản cùng các biện pháp bảo vệ dữ liệu/quyền truy cập cần thiết.
3. **Vertical Slice Development:** Làm từng tính năng hoàn chỉnh theo luồng Database Query → API Route → UI Component. Hoàn tất tính năng nào thì chạy thử trực tiếp trên giao diện tính năng đó, kèm kiểm tra có ích cho phần logic vừa đổi.
4. **Codex Review & Final Acceptance:** Sau implementation, Codex tự kiểm tra source, diff, tests/evidence, acceptance criteria và security/data boundaries liên quan; kiểm tra browser/runtime khi task yêu cầu. Không coi PASS của Anti là bằng chứng. Nếu review thấy lỗi, Codex mặc định tự sửa và chạy lại các gate liên quan. Không có correction round bắt buộc.
5. **Codex Plan, Anti Implement (Optional):** Codex đọc code thực tế, Git state và canonical docs/spec liên quan, xác minh assumptions, acceptance criteria và checks cần thiết. Với task cần delegation hoặc đủ phức tạp, Codex tạo implementation spec ngắn, đủ để thực thi. Codex tự làm fix nhỏ, regression hẹp, wiring/test fidelity bug và acceptance patch; ưu tiên Anti cho feature implementation đủ lớn, nhiều file, CRUD/UI/test đáng kể hoặc phần việc cơ học rõ ràng. Anti làm implementation và test pass ban đầu, tự sửa lỗi compile/type/test cơ học, kiểm tra browser/runtime khi cần, và không tự đổi architecture hay mở rộng scope ngoài spec. Sau handoff, Codex sở hữu review, debugging, stabilization, fixes và final acceptance.
6. **Delegation & Parallelism:** Không gọi Anti bắt buộc cho mọi task. Codex chỉ giao thêm việc cho Anti khi phần fix còn lại lớn, độc lập để parallelize, hoặc delegation thực sự hiệu quả hơn tự sửa. Không giới hạn số worker khi parallelism có ích; chỉ chạy song song với dependency độc lập, ownership/file rõ, shared state không xung đột và API contract đã chốt. Không tạo worker chỉ vì có nhiều bullet.
7. **Final Gates & Reporting:** Codex chạy các gate cần thiết sau review/fix và kết luận rõ `PASS` hoặc `FAIL`. Nếu PASS, cập nhật task/evidence vừa đủ và commit/push khi task cho phép. Nếu FAIL, nêu blocker thật còn lại; không tạo correction task chỉ để duy trì workflow. Báo cáo ngắn gồm goal/spec, Anti đã implement gì, Codex phát hiện/fix gì, tests/evidence cuối, PASS/FAIL và trạng thái commit/push.

Chỉ đọc tài liệu liên quan đến tính năng đang làm. Không bắt buộc đọc chuỗi tài liệu lịch sử, tạo work package/approved snapshot, ghi hash hoặc chấm điểm chéo AI cho thay đổi nhỏ. Task nhỏ Codex tự xử lý không cần spec artifact. Giữ nguyên thay đổi không liên quan và migration đã áp dụng. Thay đổi database về sau dùng migration mới; không tự reset/xóa dữ liệu. Danh sách dọn dẹp hàng loạt phải được người dùng xác nhận trước khi xóa hoặc chuyển thư mục. Kiểm tra đúng phần vừa sửa và báo kết quả thực tế; không coi generate Client là bằng chứng truy cập database hoặc kiểm tra toàn bộ nghiệp vụ.
