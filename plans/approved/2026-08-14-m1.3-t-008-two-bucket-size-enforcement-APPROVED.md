# M1.3-T-008 Two-Bucket Size Enforcement Amendment

> Immutable human-approved semantic amendment snapshot. No implementation, migration or database change had started when this snapshot was created.

## Status

APPROVED

## Parent Milestone

M1.3 - Auth + RLS + Storage Authorization + `record_review`

## Approved Finding

The deployed one-bucket implementation does not enforce the approved avatar maximum end to end. An authenticated owner uploaded a `5,242,881` byte `image/png` avatar successfully with HTTP `200`, and service verification confirmed that the object existed. The approved maximum is `5,242,880` bytes.

The mixed `lingora-media` bucket has a bucket-level maximum of `10,485,760` bytes to support vocabulary audio. The avatar RLS predicate using `storage.objects.metadata ->> 'size'` did not reject the oversized HTTP upload. Supabase Storage maximum-size and MIME restrictions are enforced at bucket level, while RLS remains the authorization boundary.

## Approved SEC-D8 Semantic Amendment

SEC-D8 PA2 now uses two private, non-public buckets with anonymous access denied:

| Bucket | Purpose | Bucket maximum | Allowed MIME types |
|---|---|---:|---|
| `lingora-avatars` | Learner-owned profile avatars | `5,242,880` bytes | `image/jpeg`, `image/png`, `image/webp` |
| `lingora-media` | ADMIN/service-managed vocabulary audio | `10,485,760` bytes | `audio/mpeg`, `audio/wav` |

Object-name formats are preserved:

- Avatar: `profiles/{userId}/{filename}` inside `lingora-avatars`.
- Vocabulary audio: `vocabulary/{vocabularyId}/{filename}` inside `lingora-media`.

Avatar size and MIME restrictions are enforced by `lingora-avatars` bucket configuration. Avatar SELECT/INSERT/DELETE policies use `bucket_id = 'lingora-avatars'`. Vocabulary-audio policies remain on `bucket_id = 'lingora-media'`.

## Semantics Preserved

- Both buckets remain private and anonymous access remains denied.
- Authenticated clients continue direct Storage access under PA2 RLS; no signed-URL runtime or TTL is introduced.
- Learners may upload, read, replace with a new filename/version, and delete only their own avatars.
- Existing objects are never overwritten; no UPDATE policy is introduced.
- Vocabulary audio remains ADMIN/service-managed.
- Learners cannot mutate vocabulary audio.
- Authenticated learners may read vocabulary audio only when reachable through published `Course -> Lesson -> LessonVocabulary` content.
- Only avatar owners may delete avatar objects; only ADMIN/service actors may delete vocabulary audio.
- Approved 5 MB avatar and 10 MB audio limits and their MIME allowlists are unchanged.
