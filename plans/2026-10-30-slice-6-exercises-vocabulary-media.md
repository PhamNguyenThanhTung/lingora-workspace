## Real data model and constraints

| Domain | Physical contract |
|---|---|
| Exercise membership | `LessonExercise.id` UUID; `lessonRevisionId`, composite `(itemRevisionId,itemId)` FK, positive int32 `position`, `isCore`. Unique `(lessonRevisionId,position)` and `(lessonRevisionId,itemId)`. No direct Lesson-owned Exercise table. |
| Exercise identity | `ItemIdentity.id`, origin `PRACTICE` or `ASSESSMENT`, creator, optional variant, required nonblank exactFingerprint. LessonExercise trigger requires PRACTICE. |
| Exercise content | `ItemRevision.id`, `(itemId,revisionNo)` unique, `authoringLessonRevisionId`, creator/current assignment episode, positive schemaVersion/rowVersion, `promptData` JSON object, type CHECK **MCQ, FILL_BLANK, REORDER, LISTENING, GRAMMAR**. Separate `app_private.ItemGradingSecret` one-to-one has JSON-object `gradingData`, optional object `feedbackData`. No physical prompt/answer/explanation/locale/status columns. Blueprint pins must both be NULL for PRACTICE; no assessment behavior here. |
| Vocabulary | Global `VocabularyConcept`: language FK, canonicalForm, normalizedForm, senseKey, meaningLabels object, optional phonetic/partOfSpeech/example, creator/frozenAt/rowVersion. Unique `(languageId,normalizedForm,senseKey)`; required text identity fields nonblank. No audio/image field or translation table. |
| Vocabulary membership | Revision-owned `LessonVocabularyLink.id`, vocabularyId, positive int32 position, isCore, displaySnapshot object. Unique `(lessonRevisionId,vocabularyId)` and `(lessonRevisionId,position)`. |
| Media | `MediaAsset` metadata references bucket/object; CONTENT requires assignmentId and null ownerAccountId; AVATAR has inverse ownership. `MediaBinding` owns exactly one LessonRevision or ItemRevision, positive position, AUDIO/IMAGE; SQL partial unique position per owner. No Vocabulary media relation. |

All relevant FKs use RESTRICT, not cascade. Submitted/non-DRAFT child membership and frozen/submitted item payload/grading/media writes are guarded. Vocabulary semantic identity freezes once frozenAt is set. DB guards do **not** make all old DRAFT snapshots immutable automatically: application writes must append only. Item provenance requires authoring revision's assignment to equal creation episode assignment, and createdBy to equal that episode's nextTeacherId. Do not disable or extend triggers.

## API and atomic save contract

Keep `PATCH /api/teacher/lessons/[lessonId]/draft` and `GET /api/teacher/lessons/[lessonId]`. Extend the strict save body with optional `exercises` and `vocabulary` collections; omitted collection means copy the predecessor collection unchanged, explicit `[]` means remove all from the **successor**. The production editor sends both full staged arrays on every Save. No per-child CRUD mutation routes are needed for this chosen staging contract.

Retain title/contentBlocks/changeSummary/expectedRowVersion behavior and 1 MiB streamed request bound. Add optional `expectedRevisionId: UUID|null`; supplied value must match the highest revision, with null only before revision1. Production sends it. Older accepted metadata-only calls may omit it because mandatory Lesson.rowVersion CAS already detects all append/assignment changes.

Exercise input is a strict discriminated union: `{ sourceExerciseId?: UUID, position, isCore, type, promptData, gradingData, feedbackData?: { explanation?: string } }`. `sourceExerciseId` is a membership ID in the server-read highest revision, never an arbitrary item ID/revision ID. Omit for a new exercise. Reject duplicate source IDs and positions. Source mapping, identity, episode, fingerprints, revisionNo, schemaVersion, flags and publication metadata are server-controlled. No client reparenting. Exercise edit/type switch retains sourceExerciseId but replaces the entire type-specific payload.

Vocabulary entries are a strict union:

- Retain/edit membership: `{ sourceLinkId: UUID, position, isCore }`.
- Attach existing global concept: `{ vocabularyId: UUID, position, isCore }`.
- Create or reuse identity: `{ create: { canonicalForm, senseKey, meaningLabels, phonetic?, partOfSpeech?, example? }, position, isCore }`.

Exactly one selector is permitted. Retained sourceLinkId must belong to highest revision; no arbitrary previous/other Lesson membership. Duplicate resulting vocabulary identities or positions are 409 conflicts. Existing/new global language is always checked against `Lesson → Unit → Course.languageId`; new languageId/createdBy are server-derived. No client language selector. Global concepts are never edited/deleted by these endpoints. Membership edit changes position/isCore; changing a concept means detach and attach/create an explicitly different identity. UI labels removal **Gỡ khỏi bản nháp**; no destructive global “Xóa từ vựng”. Removing an exercise also only omits it from the next snapshot.

Add small read-only `GET /api/teacher/lessons/[lessonId]/vocabulary-options?q=<term>` for exact normalized-form lookup in the course target language (bounded query, no fuzzy engine). Returns matching senses and display fields; typing/searching does not write. UI offers create new or select an existing sense. Enforce Teacher ACTIVE/assignment on this endpoint as on detail; no cross-language/global authoring endpoint.

Use a separate `TeacherLessonDetailDto`/Teacher mapper extending existing Lesson detail for authoring arrays and course target language. Grading secrets may appear only in the authorized Teacher response. Keep Admin list/detail DTOs free of gradingData/feedback secrets; shared mapper must not accidentally expose them. Teacher save returns `{ data: authoritativeTeacherLessonDetail }`, including new membership IDs, latest revision and aggregate token. BigInt remains string. GETs and mutations retain `no-store, private`, refreshed-auth headers and existing 401/403 behavior.

## Version 1 exercise payloads

These are the new **bounded runtime JSON contracts**, not claims that the DB validates their contents. All nested objects are strict; nonempty text is trimmed, bounds apply before persistence, unknown/stale fields fail server validation. No conceptId, generic DSL, learner scoring or arbitrary JSON editor.

| Type | `promptData` | private `gradingData` |
|---|---|---|
| MCQ | `{ prompt, options: [{id,text}] }` | `{ correctOptionId }` |
| FILL_BLANK | `{ prompt, sentence }`; sentence contains exactly one literal `____` | `{ acceptedAnswers: string[], caseSensitive: boolean }` |
| REORDER | `{ prompt, tokens: [{id,text}] }` | `{ correctOrder: string[] }`, exact permutation of token IDs |
| LISTENING | `{ prompt, audioUrl, options: [{id,text}] }` | `{ correctOptionId, transcript?: string }` |
| GRAMMAR | `{ prompt, sourceSentence, targetPattern }` | `{ acceptedAnswers: string[], caseSensitive: boolean }` |

Common limits: prompt/sentence/sourceSentence/targetPattern ≤4000 chars; explanation/transcript ≤4000; option/token text ≤500; IDs 1–64 chars matching `[A-Za-z0-9_-]+`; MCQ/LISTENING 2–10 options, unique IDs, exactly one existing correctOptionId; REORDER 2–30 tokens with unique IDs, duplicate token **text** allowed; acceptedAnswers 1–20 nonblank single-line entries ≤1000 chars (no duplicates after trim), Boolean caseSensitive required. Collection limits 100 exercises and 100 vocabulary links; positions 1..2147483647. Each supported type needs happy and invalid-payload coverage, including extra-field/type-switch errors. Persist schemaVersion=1 on ItemRevision and grading secret. Optional explanation lives only in feedbackData; omit SQL-null JSON fields rather than passing ambiguous Prisma `null`.

All five types are exposed. There is no exercise translation table: prompt/options are plain authored text, no invented locale relation. Lesson localized title semantics remain unchanged.

## Vocabulary identity and snapshots

Define normalizedForm server-side as canonicalForm Unicode NFC → trim → collapse whitespace to single spaces → `toLowerCase()`; preserve NFC trimmed canonical display text. This is an explicit Slice6 normalization convention, not a database-provided algorithm. canonicalForm ≤300 chars; senseKey 1–100 chars, trimmed, nonblank (UI defaults to `default`, author may choose a distinct sense). New meaningLabels accepts vi/en strings ≤2000 with at least one nonblank; phonetic ≤300, partOfSpeech ≤100, example ≤4000; empty optional fields normalize to SQL null. No new language/taxonomy subsystem.

Create/reuse checks the real unique tuple in the transaction. If existing identity has the same supplied normalized display metadata, reuse its ID with no global UPDATE; if metadata differs, return 409 `VOCABULARY_IDENTITY_CONFLICT` with safe existing ID/display so the author can explicitly select it or choose another sense. Never silently overwrite/relabel a shared/frozen record or create duplicate global rows for UI convenience. Map a concurrent unique collision recoverably; whole transaction rolls back, retry uses existing identity. Within one request reject two entries resolving to the same concept.

New attachment snapshot is server-built from the selected global concept: `{schemaVersion:1,languageId,canonicalForm,meaningLabels,phonetic,partOfSpeech,example}`. Retaining a predecessor link copies its **stored displaySnapshot byte-for-JSON-value**, not current global metadata; position/isCore may change in the successor. Snapshot is the historical display source. All old links/global rows remain unchanged, including when an externally mutable global concept later changes. Snapshot/version shapes not understood by this runtime must block editing rather than be dropped/reconstructed. Preserve untouched localized values in supported snapshots. Global-concept editing is out of scope; no misleading edit controls.

## Media boundary

Actual tables exist, but Codex read-only DEV verification found **MediaAsset=0, MediaBinding=0, no `storage.buckets` row for `lingora-media`**, and the repo has no safe upload/storage runtime. Defer uploads, bucket provisioning, managed asset CRUD/selection, signed URLs, provider calls, playback/embeds and physical MediaBinding creation. No schema/config/secret additions.

LISTENING supports a bounded **external audio reference** in its real JSON `promptData.audioUrl`; this adds no physical URL column and does not pretend to provision a MediaAsset. Validate with URL parsing: max2048, HTTPS, public DNS hostname with a dot, no username/password, no query/fragment, no custom port except443, no IP literals or localhost/.localhost/.local/.internal hostnames. Reject javascript/data/file/http/protocol-relative inputs. Store normalized URL; never resolve/fetch it server-side or embed/play it in the UI. It is a reference, not a verified playable/uploaded asset. UI explains this and uses a plain labeled input. Reject secrets/signed query URLs through the no-query rule. Other arbitrary media paths/URLs/JSON keys are not accepted.

An existing draft containing physical Lesson/Item media bindings, foreign schemaVersion/payloads, unsupported snapshots, orphan authored items, non-PRACTICE/mismatched item relations, attempts or assessment associations remains read-only with `UNSUPPORTED_DRAFT_CONTENT`. Do not silently lose those associations. This deliberately replaces only Slice5's blanket blocker for **fully understood Slice6 exercises/vocabulary**. No media subsystem architecture is invented.

## Snapshot creation and concurrency

Extend the existing save transaction rather than adding a second write path:

1. Parse/bound body, then lock verified Teacher Account `FOR NO KEY UPDATE`; require role TEACHER and ACTIVE inside the transaction (auth middleware alone is insufficient).
2. Lock Lesson `FOR UPDATE`, then ContentAssignment `FOR UPDATE`, check assignment ownership **before** CAS (opaque404 for unassigned/nonexistent). Preserve accepted lifecycle/reassignment lock order and fail closed on lock errors.
3. Check canonical positive int64 expectedRowVersion against Lesson.rowVersion; highest revision across **all statuses** and optional expectedRevisionId must match. Verify latest assignment-history nextTeacherId/scopeGeneration as in Slice5.
4. Require highest revision DRAFT with no submission/approval/publication/ended facts; validate whole predecessor structure/associations. Do not weaken Slice5 workflow checks. A new Lesson may stage children before its first Save.
5. Load source memberships/items/secrets/snapshots from that highest revision in the transaction. Verify sourceExerciseId/sourceLinkId belongs to it; item's composite IDs and authoringLessonRevisionId match source revision; PRACTICE, schemaVersion1, no blueprint pins/omitted/frozen/unsupported associations. Validate omitted collections too before copying; reject unsafe legacy content as read-only.
6. Lock retained ItemIdentity rows in sorted UUID order before assigning new per-item revision numbers. Append LessonRevision max+1 with prior pointer and current assignment episode/Teacher; preserve accepted title merge, content and server metadata/coverage behavior, activeRevisionId unchanged.
7. For **each retained exercise, even unchanged**, reuse ItemIdentity but INSERT a new ItemRevision (max revisionNo for that identity +1), fresh grading secret and fresh LessonExercise membership owned/authored by the new LessonRevision. New exercise inserts a PRACTICE ItemIdentity then revision1. New ItemRevision creator/episode are the current Teacher/current episode, not copied old creator. Preserve supported source practiceSkillIds/practiceCoverageSnapshot; new defaults empty/null, never accept client coverage edits. Do not UPDATE old identity/revision/secret/membership or set old isDraftOmitted. Identity keeps its original exactFingerprint; each new revision gets its own fingerprint.
8. Required exactFingerprint is server-derived SHA-256 of deterministic canonical JSON of type/schemaVersion/promptData/gradingData/feedbackData (sorted object keys, arrays ordered); identical content is deterministic. Set new identity fingerprint from its initial content. This is a domain fingerprint, not a code audit manifest/dedup engine. Clients cannot supply it.
9. Retained VocabularyConcept IDs are shared; insert fresh links with preserved snapshots. Resolve new/create/reuse/attach operations, check target language, build new snapshots. Never mutate global concept state. Removed members simply have no successor link/revision copy; all predecessor records remain intact.
10. Bump Lesson.rowVersion exactly once, fetch authoritative Teacher DTO and commit. Any validation/race/insert/aggregate/DTO failure after writes must roll back **all** new rows/global concepts and token changes. Returning an error from a transaction after mutations must not accidentally commit partial rows; validate before writes or throw a controlled rollback error.

Lesson/assignment locks serialize same-Lesson requests; ItemIdentity locks protect max+1 even if another legitimate caller references the identity. Two same-token saves: one200/one409 with one complete successor. Disable/reassign racing after route auth must deny correctly. Different source IDs from a prior revision/other Lesson are404 `RELATION_NOT_FOUND`, even if globally valid. No stale child writes or in-place historical edits.

## Error contract and editor behavior

Keep `{error:{code,message,fields?}}`; do not expose Prisma/storage/provider errors. Use400 INVALID_ID/MALFORMED_JSON/VALIDATION_ERROR with precise array/type field paths;400 PAYLOAD_TOO_LARGE (accepted Slice5 status retained);415 UNSUPPORTED_MEDIA_TYPE;401 accepted session-loss modal;403 FORBIDDEN/ACCOUNT_INACTIVE/FORBIDDEN_ORIGIN;404 LESSON_NOT_FOUND or RELATION_NOT_FOUND;409 STALE_LESSON, DRAFT_NOT_EDITABLE, INCONSISTENT_ASSIGNMENT_HISTORY, UNSUPPORTED_DRAFT_CONTENT, DUPLICATE_EXERCISE_POSITION, DUPLICATE_VOCABULARY_POSITION, DUPLICATE_VOCABULARY_LINK, VOCABULARY_IDENTITY_CONFLICT, VOCABULARY_LANGUAGE_MISMATCH or REVISION_CONFLICT;503 SERVICE_UNAVAILABLE. Invalid audioUrl is a field-level VALIDATION_ERROR. Blocked destructive DELETE is absent by design; unsupported history is explicit read-only, never an application cascade.

Add simple sections after paragraphs in real `/my-lessons/[lessonId]` editor. Use baseline form/modal primitives, explicit add/edit/remove, numeric position/core checkbox. Small type-specific controls; switching type resets its payload and errors so old fields do not submit. Explain changes save together with the Lesson; no child false-success before Save. Preserve staged input on400/409/503/network failure, show actionable field/conflict errors, allow retry. Pending disables duplicate submissions/navigation/mutation controls synchronously. 401/403 follow accepted session-loss/access-denied flows. STALE_LESSON keeps typed state, prevents further Save until explicit latest-content reload, then replaces **all** metadata/child arrays/source IDs/revision/token together. A late response must not overwrite a newer authoritative UI. Successful Save reconciles all arrays/IDs/token from server DTO and clears changeSummary. Vocabulary removal never deletes global concepts. No drag/drop, player or generic JSON page builder.
