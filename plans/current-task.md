- **Auth contract:** Mỗi protected request xác minh identity bằng SSR client và `auth.getUser()`, lấy provider UUID, đọc lại Account từ DB, rồi kiểm tra tồn tại + `ACTIVE` + `ADMIN`. Không cache role/status xuyên request, không tin user metadata/client role hay riêng `getSession()`; backend checks vẫn áp dụng cho mọi read/mutation. Dùng `getUser()` để có xác nhận mới từ Auth server theo [SSR guide](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs&package-manager=npm) và [session revocation guidance](https://supabase.com/docs/guides/auth/server-side/advanced-guide).

| Trường hợp | Protected request / điều hướng |
|---|---|
| Chưa đăng nhập | API 401; page đưa về login. |
| Session invalid/expired, refresh không thành công | 401; luồng hết phiên/draft/focus theo frozen baseline, không tiếp tục thao tác. |
| Auth user hợp lệ nhưng thiếu Account | 403, không tự tạo Account hoặc cấp quyền từ metadata. |
| Account PENDING hoặc DISABLED | 403 ngay request tiếp theo dù token chưa hết hạn. |
| ACTIVE TEACHER/LEARNER | `/languages` và CRUD trả 403; Teacher sau login tới safe holding view theo baseline, không tạo redirect loop. |
| ACTIVE ADMIN với provider identity hợp lệ | Cho phép list/CRUD sau validation nghiệp vụ và DB constraints. |
| Auth service hoặc DB không khả dụng | Fail closed, lỗi dịch vụ 503 phù hợp; không cấp quyền, không biến outage thành kết luận credential sai. |
