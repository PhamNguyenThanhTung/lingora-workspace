## Read contract

A small server-only audit module owns validation, fixed display codes/DTO, cursor handling and parameterized query. A small shared types/constants file is fine when needed by the client; it must not import DB/server-only code. No new dependency, generic report framework, joins to Auth, aggregate counts, export, event details/raw JSON, search, mutation, new event emission or audit retention behavior.

`GET /api/audit-events`:

1. Obtain cookies/SDK response headers and verify required ADMIN before parsing/querying the audit feature. Deny anonymous 401, Teacher/Learner/non-ACTIVE 403; existing provider/Account outage is 503. Never authorize from a cookie role, JWT decode, URL or client prop.
2. Accept only `from`, `to`, `action`, `outcome`, `cursor`, each at most once. Reject unknown/duplicate keys, malformed values and oversized cursor with 400 generic VALIDATION_ERROR; do not echo input. Fixed page size **50**, never a caller-selected SQL limit.
3. `from`/`to` are either both omitted on the first request (server fixes last 7 days through its current time) or both valid canonical UTC ISO millisecond timestamps (`YYYY-MM-DDTHH:mm:ss.sssZ`, real calendar values). Require `from < to` and span at most **31 days**. Query interval is `[from,to)`. API returns normalized effective filters; UI always sends explicit effective bounds on subsequent requests. No implicit fallback on invalid dates.
4. Optional action is one of the five current action codes or `OTHER`; omitted means all. OTHER matches the complement of those five exact codes. Optional outcome is SUCCESS / DENIED / FAILURE; omitted means all. No arbitrary raw action filter, substring filter, dynamic options or URL-to-SQL interpolation.
5. Response: `{ data: AuditEventDto[], filters: { from, to, action: code|null, outcome: code|null }, nextCursor: string|null }`. DTO is exactly `id`, `occurredAt`, `actorKind`, `actorId` (nullable), `action`, `targetType`, `targetId` (nullable), `outcome`. IDs are DB UUIDs, never names/email. `actorKind` uses known fixed codes (defensive OTHER fallback); `action` uses five fixed codes or OTHER; `targetType` is ACCOUNT or OTHER; `outcome` uses the three fixed codes (defensive OTHER fallback). Do not return verifiedAuthSubjectId, reason, safeContext, correlationId, createdAt, targetVersionId, Auth/profile data, raw unknown strings or DB errors. VERIFIED_AUTH_SUBJECT displays a generic verified subject label and no subject identifier; target UUID remains useful for current activation events.
6. Use an explicit SQL projection with CASE allowlists for action/target_type (prefer defensive fixed mappings for actor/outcome too), not `SELECT *` or raw row spreading. SQL must not fetch sensitive omitted columns. Map fixed codes to fixed Vietnamese labels in UI; unknown stored payloads appear only as “Khác”.
7. Order `occurred_at DESC, id DESC`; fetch 51, return first 50, generate cursor from last returned row only if an extra row exists. Next predicate is `(occurred_at, id) < (cursorTimestamp::timestamptz, cursorId::uuid)`. All dates, UUIDs, filters and limit are bound values through Prisma `$queryRaw`/`Prisma.sql`; no `$queryRawUnsafe` or concatenated SQL. Filters and ordering are server-owned.
8. Preserve microseconds end to end: SQL selects `to_char(occurred_at AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')` as occurredAt; never obtain the cursor timestamp through a JS Date. Cursor is bounded (max 1024 encoded characters), canonical base64url JSON with exact version 1, exact six-digit UTC timestamp, UUID and normalized effective from/to/action/outcome. Reject invalid encoding/JSON, extra/missing keys, impossible timestamps, bad UUID, wrong version, timestamp outside range or mismatched filters. A cursor request requires explicit from/to matching the embedded bounds. Cursor is an untrusted position, not an authorization token; signing is unnecessary. Do not reduce six-digit precision in cursor decoding or SQL cast.
9. Return all success/validation/auth/service/error responses with private no-store, preserve existing SDK refresh headers/cookies and ensure final Cache-Control contains `no-store, private` even if SDK supplied a different cache header. Generic unavailable 503 for known connectivity failures, generic 500 otherwise; never expose exception text/query/connection data or log event payloads. Wrap client acquisition/query exceptions as well as mapping failures. Page is force-dynamic; client fetch is no-store.

Pagination is a bounded browse of an append-only log, not a transaction snapshot. Fixed upper bound stops ordinary newer arrivals entering later pages; no offset/count query. Backdated concurrent insertion is not promised snapshot isolation. Retained exact timestamps and UUID tie-breaker prevent skips/duplicates from timestamp truncation.

## Page and interaction

- Server page verifies ADMIN before any audit read. Anonymous redirects to `/login`; denied staff render existing AccessDeniedView, auth availability uses ServiceUnavailableView. After success render AppShell plus actual audit component with the server's initial result/effective bounds. Do not add a runtime test-auth override or bypass.
- Add one Admin-only Sidebar entry “Nhật ký hoạt động” at `/audit-events`, active-state handling and `aria-current` for this link. Teacher navigation and logout/draft cleanup behavior remain intact. Leave AppShell itself unchanged.
- Reuse existing catalogue/table styles; only small local style additions if genuinely needed. Heading and brief copy clearly say this is the stored operational audit log; absence of events is not proof no activity occurred.
- Show timestamp (with explicit displayed timezone), fixed actor label/account UUID where available, fixed action, fixed target type/UUID and outcome. Use `<time dateTime>` and semantic table/caption/column headings; UUIDs must wrap without breaking the layout. No HTML insertion or raw stored strings.
- Labeled from/to controls (UI may use datetime-local and convert through UTC), finite action/outcome selects, Apply and Reset. Defaults are last 7 days; show the 31-day maximum and validation accessibly. Applying/resetting filters starts the first page and clears prior pagination history. Retain input on validation/network error.
- Loading/initial failure, useful empty state, recoverable error with Retry, and pending state must be visible and accessible (`role=status`/alert, `aria-busy`). Disable duplicate Apply/Next/Back while pending. Avoid stale request races (abort or request sequence) and never replace good data with an obsolete response. Failed Next/Back must not advance navigation state or show false success.
- Next exists only when nextCursor exists. Back uses a short client stack of prior request cursors for the same fixed effective filters (first page has null cursor); no reverse SQL query is needed. Changes to filters reset this stack. Keep displayed rows, effective filters and cursor consistent. Handle later 401/403 safely without retaining privileged rows as a current successful view; generic availability retry for 503. Browser history/URL persistence is not required.
