## Implementation Review Checklist

The following implementation details still require review before approval; they may not change ADR-003 semantics:

1. **Entity/field mapping:** exact Prisma scalar types, defaults, database column names and timestamp precision for every approved logical field.
2. **Enum mapping:** confirm only approved enum values, including `LEARNER | ADMIN`, three Exercise types, ProgressStatus and ChatRole.
3. **FK deletion audit:** enumerate every actual Prisma relation and map it one-to-one to the complete ADR-003 deletion matrix, including the approved Language/locale and ChatScenarioTranslation actions. Any newly missing relationship returns the plan to REVIEW.
4. **Index/query audit:** map every proposed index to a `docs/05` requirement or concrete planned query; remove speculative indexes and identify missing FK-source indexes.
5. **Normalization implementation:** document the minimal deterministic `normalizedTerm` function used later by Admin, seed and trusted writes; do not add alias/sense/lemma semantics.
6. **Publication mechanism boundary:** schema supports validation, but trusted publication function/transaction ownership must not be accidentally implemented as M1.2 RLS/RPC work.
7. **Exercise JSON checks:** decide which universal checks are feasible in migration SQL versus later trusted application validation, without pretending Prisma validates JSON shape.
8. **Chat sequence allocation:** schema adds positive sequence and uniqueness; allocation transaction belongs to the later trusted write path.
9. **Pooler/Prisma compatibility:** confirm exact Prisma version and Session Pooler parameters without enabling direct IPv6 or Dedicated IPv4.
10. **Migration apply checkpoint:** generated SQL must be reviewed and the intended Supabase project identified without logging credentials before any apply command.
