## Required findings

1. **P1 — Learner denial/logout revokes other sessions.** `lingora-web/src/app/api/auth/login/route.ts:162` and `lingora-web/src/app/api/auth/logout/route.ts:31` call `signOut()` without scope. Installed `node_modules/@supabase/auth-js/src/GoTrueClient.ts:4069` defaults to `global`. An Admin/Teacher entering valid credentials at learner login obtains a learner-origin session, fails the product role guard, then revokes that identity's existing staff refresh sessions. Separate cookies do not prevent this provider-side regression. Use `signOut({ scope: 'local' })` for learner-origin cleanup/logout; assert the actual provider request uses local scope and preserves unrelated cookies.

2. **P1 — Required production-page/session evidence is absent.** `lingora-web/tests/feature/login-flow.test.mjs:82` exercises handlers/API with a shared mutable cookie map, never production login/home pages or observable home UI. Its final logout assertion manually removes learner cookies, so it can hide broken logout persistence. `tests/feature/harness/isolated-harness-entry.tsx:59` renders fixed `HomeView` props; `mock-next-navigation.ts:39` replaces routing with window markers; `isolated-server.mjs:92` implements a second login/logout API. Neither actual page is imported. Removing `HomePage` guard/loader wiring would leave these checks unaffected. Add the required controlled flow through actual LoginPage/LoginForm -> real login handler -> cookies -> actual HomePage/guarded loader -> visible identity/context, with real production callback behavior; cover 401 redirect and 403/409/503 outcomes/retry through the actual page. Do not manually repair logout state in its proof. Also replace misleading transport tests: `auth.test.mjs:510` only checks `client.auth` (captured cookies unused), and `:523` supplies no session, proving no refresh. Exercise a refreshable expired access token with the real SDK, chunk/flag propagation, downstream refreshed request cookies, and SDK Cache-Control/Expires/Pragma on relevant success/error/redirect responses. Retain isolated view checks as complementary coverage.

3. **P2 — Confirmation behavior differs from the contract.** `lingora-web/src/app/api/auth/login/route.ts:112-149` maps provider `email_not_confirmed` to 401 `INVALID_CREDENTIALS`, losing the required safe confirmation guidance/403. Bounded reproduction invoked the real handler with a mocked token response `400 {code:'email_not_confirmed',message:'Email not confirmed'}` and observed that exact 401. Handle the provider code explicitly and test the real handler. `src/server/auth/index.ts:239` also accepts generic `confirmed_at` without `email_confirmed_at`; enforce email confirmation specifically and test a generic/phone-confirmed user with no confirmed email.

4. **P2 — Malformed parent/framework joins can return successful foreign summaries.** `lingora-web/src/server/context/loader.ts:137-176` checks relation presence, course-language scalar equality, and level framework scalars, but never compares `language.id` to `languageId`, `course.id` to `courseId`, or `course.framework.id` to `course.frameworkId`. A bounded query-double reproduction with all three joined IDs mismatched returned 200 and serialized the mismatched language/course/framework objects. Complete these explicit parent checks and add isolated corruption cases expecting safe 409 `CONTEXT_INCONSISTENT`, as required by the spec. No live corrupt inserts are needed.
